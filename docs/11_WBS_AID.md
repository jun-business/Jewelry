- 실행 방식 결정: **fan-out 없음 — PM(claude-opus-5-5·high) 직접 구현**. 근거: 단일 저장소·단일 프로세스, 모듈 간 결합(전이 서비스·스키마)이 강해 병렬 worker의 이득보다 계약 충돌 위험이 큼. 그래서 AID는 worker 지시서가 아니라 **각 work의 입력·DoD·검토 기준 기록**이며 콜드 리드 검사는 `N/A(dispatch 없음)`. 계약 동결(RTM 7부)은 그대로 적용한다.

## AID 공통 검토 기준(Criterion Lock — 핵심 외 모듈의 경계 케이스, 조정 계획 규칙)
- 모든 쓰기 동작: 트랜잭션 1개, 실패 시 부분 커밋 0, 감사 이벤트에 고객 개인정보 값 0.
- 모든 사람 동작: 역할 검사가 서버에 있음(BD-008), 거부 시 PDS 문구.
- 모든 화면: 1차 문구에 영문 코드 0, 버튼 비활성 시 `aria-disabled` + 이유 연결, 대표 버튼 1개.
- 입력 경계: 금액 음수·문자 거부, 빈 필수값 422/409 규칙(BD-006), 파일 형식·크기 거부(E-24).
- TC-U ID 범위: DD-010 표.
