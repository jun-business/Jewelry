# 관측 기준 목록 (맹검 역번역 입력)

- EXP-001 : Given 기본 설정 / When 어느 R1 화면을 열면 / Then 본문 글자 16px 이상, 보조 글자 13px 이상, 화면의 1차 문구에 영문 상태 코드(`OWNER_REVIEW` 등)가 노출되지 않는다(한국어 라벨, 코드는 보조 표기만), 글자 크기 “크게” 설정이 있다.
- EXP-002 : Given 주문들이 여러 상태에 있음 / When 주문 목록을 열면 / Then 큐 탭 = {검토 필요(신규·수락 검토), 정보 부족, 대기, 시안·견적, 결제 확인, 제작, 지연·이슈, 배송, 종료, 전체}이 건수와 함께 보이고, 각 행에 주문ID·고객 표시명·상품·현재 단계·다음 조치·승인 상태·최종 변경이 보인다. 상세에서 뒤로 오면 선택 큐·검색어가 유지된다(URL 쿼리).
- EXP-003 : Then 동기화 마지막 성공이 폴링 간격×3(기본 15분) 초과면 경고, 백업 마지막 성공 26시간 초과면 경고, 디스크 여유 10% 미만 경고, 미해결 결제 이슈 ≥1이면 위험 표시. 각 경고는 해결 화면으로 가는 링크를 가진다.
- EXP-004 : Given 승인 대상 / When 승인 버튼 → 확인 대화상자 / Then 대상 버전·조건 목록·승인자 이름이 표시되고, 체크박스는 기본 미체크, 거절·보류·상한초과 수락은 사유 필수. 저장 시 승인자·시각(KST 표시/UTC 저장)·사유·대상 버전이 감사로그에 남는다. 승인 권한은 역할로 제한된다(제작 승인 = 아버님 역할). **일괄 승인 기능은 없다.**
- EXP-005 : Given 활성 수락 3건 / When 4번째를 수락 / Then 경고 대화상자에 “동시 진행 3/3”이 표시되고 **사유 입력 시에만** 수락(상한 초과 기록). 새 문의는 계속 저장되고 `WAITLISTED` 표시를 받을 수 있다. 시스템은 어떤 경우에도 자동 수락하지 않는다.
- EXP-006 : 15분 비활성 시 잠금(설정 가능), 잠금 60초 전 경고와 “계속 사용” 버튼, 재로그인 후 원래 URL로 복귀. 비로그인 상태에서 고객정보·파일 URL 접근 시 로그인 화면(파일은 403/리다이렉트).
- EXP-007 : 고객 응답 지연 = `NEEDS_INFO` 또는 고객 동의 대기 상태가 3일 초과(설정), 제조 납기 위험 = 공장 예상 수령일 경과 또는 고객 약속일까지 남은 일수 < 남은 단계 최소 소요(설정, 기본 3일 이내). 두 종류는 다른 라벨·아이콘으로 대시보드 별도 묶음에 표시된다. 고객에게 자동 발송 없음.
- EXP-008 : 견적 화면에서 내부값(공장 예상원가·변동비·마진·위험 플래그)은 “내부 전용” 표지가 붙은 별도 영역에 있고, 고객 안내용 견적 문서(인쇄/복사)의 HTML·텍스트에 내부값 문자열이 0건.
- EXP-009 : 외부 출처 데이터(Google 응답, 결제 대조, 카카오 기록) 옆에 “마지막 동기화 시각”이 보인다. 카카오 영역에는 항상 “수동 기록 — 실시간 수신 아님”이 표시된다. PC 재기동 후 첫 화면에 “PC 중단 추정 구간 및 백필 결과”가 표시된다.
- EXP-010 : KST 기준 공휴일(설정의 휴무일 목록)에는 “수락” 버튼이 비활성이며 이유 문구가 버튼 옆에 보인다(보류·정보요청은 가능). 00:00–07:00(설정)에는 앱 내 신규 알림 배지를 띄우지 않고 다음 업무 시각에 묶어 표시한다. 평일 날짜에 CAD 일정을 자동 확정하지 않는다(주말 슬롯만 제안).
- EXP-011 : 초안은 승인 전 “복사” 버튼이 비활성(이유 표시). 승인 후 문구가 잠기고 “복사”와 “발송 완료 기록”이 활성. 승인 후 수정하면 재승인 필요. 모든 초안에 CS 레벨(L0~L3)과 참조 정책 ID/버전이 표시된다.
- EXP-012 : 주문 상세에 (1) 대외 5단계 진행 표시, (2) 현재 내부 단계, (3) 다음 조치 1개와 그 전이 조건 체크리스트(충족/미충족), (4) 감사 타임라인. 15개 정상 전이를 이 화면에서 모두 수행 가능.
- EXP-013 : 전이가 막히면 버튼 옆에 미충족 조건이 문장으로 나열된다(툴팁만으로 숨기지 않음). 서버도 같은 조건으로 거부하고 오류 메시지가 같은 문구다.
- EXP-014 : 계정 역할 `maker`(아버님)·`operator`(사업 책임자). 제작 수락·견적 승인·상세 CAD 착수·발주·QC·CS 승인은 `maker`만, 결제 증빙 대조·정책/설정·Gate 상태 기록은 `operator`만(둘 다 조회 가능). 권한 없는 버튼은 비활성+이유.
- EXP-015 : 모든 내부 단계가 정확히 하나의 대외 단계로 매핑된다 — 접수 {INQUIRY_RECEIVED, AI_BRIEF_READY, OWNER_REVIEW} · 시안·견적 {FREE_CONCEPT, QUOTE_APPROVED, CUSTOMER_ACCEPTED} · 결제·제작준비 {PAYMENT_PENDING, INITIAL_PAYMENT_VERIFIED, DETAIL_CAD, CUSTOMER_DESIGN_APPROVED} · 제작 중 {FACTORY_SENT, FACTORY_RECEIVED} · 배송·완료 {QC_PASSED, FINAL_PAYMENT_VERIFIED, SHIPPED, CLOSED}. 거절·취소 종료는 대외 “종료”로 별도 표기. 고객용 문구(CS 초안·견적 문서)에는 대외 단계명만 쓰인다.
- EXP-016 : 설정의 Gate 보드에 9개 Gate의 상태(미통과/통과·증거·기록자·일시)를 운영자가 기록한다. `GATE-SS-02`·`GATE-LEGAL-01` 미통과면 결제 요청 생성 화면에 “실거래 비활성 — 시험 모드” 배너가 표시되고 결제 요청은 `test` 표지로만 생성된다. `GATE-CS-01` 미통과면 자동 발송 기능 자체가 없다(R1 수동). `GATE-REMOTE-01` 미통과면 서버는 127.0.0.1에만 바인딩한다.
