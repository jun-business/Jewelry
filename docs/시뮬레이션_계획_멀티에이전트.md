## 1. 역할

| agent | 하는 일 | 하지 않는 일 |
|---|---|---|
| **중앙(이 세션)** | 순서 진행, 하위 agent에 단계별 상황 전달, 받은 행동을 실제 폼·앱에 실행, 결과 기록, 마지막 취합 보고 | 페르소나 대신 판단하지 않음 |
| **고객 페르소나 agent × 5** | 자기 페르소나로 Form A 답변·카톡 메시지·Form B 선택·결정(수락/흥정/취소/하자 주장)을 정해진 형식으로 낸다. 각 단계 뒤 고객 입장 피드백 | 브라우저 조작·폼 제출(중앙이 실행) |
| **법률 검토 agent** | Form B v1.3 고지, 견적서 개별 제작·손해 사유, 단계별 환불 처리(R2·R6)와 증거 묶음을 전자상거래법 관점으로 검토 — 위험도·논점·고칠 문구 | 법률 자문 아님(최종은 변호사 검토, GATE-LEGAL-01) |
| **아버님·운영자 사용성 agent** | 단계마다 화면 캡처와 조작 기록을 보고 “아버님이 혼자 할 수 있나”, 운영자 부담을 평가 | 실행 |

총 8개(중앙 제외 7) — 권장 규모(10 미만) 안.

## 3. 진행 순서 (단계마다 중앙이 보고)

1. **준비**: 기준 커밋 고정·시험 260+ 통과 확인, 개발용 앱 새로 시작(빈 데이터, 시험 계정 2개), 정책 초안 승인(운영자), Form A·B 게시·문항 일치 확인.
2. **Form A 5건 제출**(실제 폼, 페르소나 답변) → 앱 수집·AI 정리 확인.
3. **상담(카톡)**: 페르소나 agent가 만든 대화문을 앱 ‘카카오톡 대화 붙여넣기’로 기록 → AI 정리·답변 초안 → 아버님 승인 → 발송 기록.
4. **아버님 검토**: 수락·정보 요청·대기·(필요 시) 거절.
5. **시안·견적**: 개별 제작 특성·손해 사유 작성 → 청약철회 고지 AI 검토(실제 AI 키) → 사람 최종 판단 → 승인.
6. **Form B 5건**(실제 폼, 같은 Google 계정) → 수집 → 운영자 본인 확인(‘이 Google 계정 기억’은 P1에서만 켜고, P3에서 ‘다른 고객’ 경고가 뜨는지 확인 후 끔).
7. **결제·제작**: 가짜 네이버 주문번호로 예약금·잔금 확인 입력, CAD·최종 승인(카톡 증빙)·발주·수령·검수·발송 — 날짜는 실제 날짜로 입력.
8. **취소·환불**: P4(R2), P5(R6) 접수 → 법률 검토 agent 의견 → 결정·환급 기록.
9. **취합**: 페르소나별 여정 기록, 문제 목록(심각도), 법률 검토 메모, 사용성 평가 → `docs/시뮬레이션_<날짜>_보고.md`.

## 4. 승인·제약

- **실행 전 사업 책임자 승인**을 받는다(이 계획 확정 + 실제 폼 제출 허락: Form A 5건, Form B 최대 7건(재발행 포함)).
- 실제 사람 정보 금지: 이름은 가상, 전화는 `010-0000-00xx`.
- 결제는 흉내만(실제 구매·결제·환불 없음). 카카오톡은 대화 붙여넣기로만.
- 실행 중 코드 수정 금지(발견은 기록만) — 다른 세션 작업도 멈춘 상태에서.
- 법률 검토는 자문이 아님.
