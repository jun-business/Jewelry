## 1. 디자인 원칙

| # | 원칙 | 의미 | 이 원칙이 이기는 상충 |
|---|---|---|---|
| P1 | **지금 할 일 하나** | 모든 화면은 “다음에 누를 것 하나”를 가장 눈에 띄게 둔다. 주문 상세의 대표 버튼은 언제나 1개. | 정보량 < 행동 명확성 |

### 4.1 토큰 사용 규칙
- 원본: `design-tokens.json`. CSS 변수 이름 `--jos-<group>-<name>`(예: `--jos-color-primary`, `--jos-space-4`). 컴포넌트 CSS는 토큰 변수만 참조하고 HEX 값을 직접 쓰지 않는다.
- 테마: `<html data-theme="light|dark">`. 기본값 = 사용자 설정 → 없으면 `prefers-color-scheme`.

### 4.4 간격·모양·깊이·움직임
- 간격 4px 단위: 4·8·12·16·20·24·32·40·48·64. 카드 내부 패딩 20(≥900) / 16(<900). 섹션 간 32.
- 모서리: 입력 4, 버튼·카드 8, 대화상자 12, 칩 pill.
- 깊이: 카드 shadow-1 + border, 팝오버 shadow-2, 대화상자 shadow-3 + 배경 dim(rgba(28,27,24,.48)).
- 움직임: 120ms(hover·press), 200ms(패널·토스트), 280ms(시트). `prefers-reduced-motion: reduce`면 전부 0ms(투명도 전환만 허용).
- z-index: sticky 10 · drawer 30 · dialog 40 · toast 50 · lock 60.

### 4.6 아이콘
- Lucide(ISC) SVG 스프라이트를 `static/icons.svg`로 동봉(외부 요청 없음). 크기 20(기본)·16(칩)·24(빈 상태). 획 1.75.
- 의미 고정: 확인=check-circle, 경고=alert-triangle, 위험=octagon-alert, 정보=info, 내부 전용=lock-keyhole, 시험 모드=flask-conical, 동기화=refresh-cw, 수동 기록=hand, 복사=copy, 외부 링크=external-link, 시계=clock, 버전=git-commit(“v” 배지와 함께).
- 구현 스프라이트 id(`static/icons.svg`, 자체 제작)는 짧은 별칭을 쓴다: check-circle→`check`, alert-triangle→`alert`, octagon-alert→`octagon`, x-octagon→`xoct`, lock-keyhole→`lock`, flask-conical→`flask`, refresh-cw→`refresh`, external-link→`external`, git-commit→`commit`, git-branch→`branch`. 코드는 별칭만 쓴다(14_TR DEF-004).
- 아이콘만 있는 버튼은 `aria-label` 필수 + 툴팁. **주요 동작(대표 버튼)은 아이콘만으로 만들지 않는다.**

### 4.7 컴포넌트 명세
모든 상호작용 컴포넌트의 공통 상태: default · hover · focus-visible(2px `focus` 링 + 2px 간격, 대비 ≥3:1) · active · disabled(투명도 대신 `text-subtle`+`surface-sunken`, 이유 문장 연결) · loading(스피너 + `aria-busy`, 라벨 유지).

#### C-01 Button
- 종류: `primary`(화면/영역당 1개), `secondary`(테두리), `tertiary`(텍스트), `danger`(거절·취소·삭제 요청), `danger-secondary`.
- 크기: md 40px(기본), lg 44px(하단 조치 바·대화상자 확인·터치 환경 <900 전부), sm 32px(표 행 내부, 데스크톱 전용 — 터치 목표 24×24 이상 확보).
- 라벨: 동사로 끝나는 2~8자(“수락”, “견적 승인”, “결제 확인 입력”). 마침표 없음.
- **비활성 규칙**: `disabled` 대신 `aria-disabled="true"`를 써서 포커스는 가능하게 하고, `aria-describedby`로 아래 C-14 차단 사유를 연결. 클릭 시 차단 사유 영역으로 스크롤·강조(동작하지 않음).
- 로딩: 클릭 후 서버 응답까지 라벨 앞 스피너, 중복 제출 방지(같은 폼 재제출 차단).

#### C-02 TextField / Textarea
- 라벨은 항상 보이는 위쪽 라벨(placeholder를 라벨로 쓰지 않음). 필수 표시는 라벨 뒤 “(필수)” 텍스트(별표 단독 금지).
- 도움말: 라벨 아래 body-sm `text-muted`. 오류: 필드 아래 `danger-text` + 아이콘, `aria-invalid="true"`, `aria-describedby`에 오류 id.
- 높이 44px, 테두리 `border-strong` 1px, 포커스 시 2px `focus`.
- Textarea: 최소 4행, 자동 높이(최대 16행), 글자 수 제한이 있으면 우하단 “120/500”.

#### C-03 MoneyInput
- 입력 중 천 단위 쉼표 자동, 오른쪽 정렬, 접미 “원”(시각 요소, 값에는 미포함), 정수만(원 단위). `inputmode="numeric"`.
- 음수 불가(환불은 별도 역분개 화면에서 “환불 금액”으로 양수 입력).

#### C-04 Select / Combobox / Radio / Checkbox / Switch
- 선택지 ≤5면 Radio(세로), 6 이상이면 Select. 검색 필요하면 Combobox(키보드 ↑↓·Enter·Esc).
- 승인 대화상자의 확인 체크박스는 **항상 기본 미체크**.
- Switch는 즉시 적용 설정(개인 표시 설정)에만. 저장 버튼이 필요한 폼에는 Checkbox.

#### C-05 DateTimePicker
- 표시 “2026년 10월 16일(금)” / 입력은 네이티브 `type=date`·`type=time`(접근성·모바일 키보드). 모든 시각은 KST로 입력·표시, 저장은 서버가 UTC 변환.
- 휴무일은 달력에서 회색+“휴무” 표기(일정 화면).

#### C-06 FileUpload
- 드롭존 + “파일 선택” 버튼(키보드 가능). 허용 형식·최대 크기를 드롭존 안에 문장으로 표시(“JPG·PNG·PDF, 최대 30MB” / CAD: “3DM, 최대 200MB” / STL: “STL, 최대 200MB”).
- 업로드 후 FileCard(C-17)로 바뀌고 해시 계산 완료까지 “확인 중…”.

#### C-07 StatusChip
- 모양: pill, 높이 24, 아이콘 16 + 라벨 caption(13px 500). 종류별 색:
| 종류 | 색 | 예 |
|---|---|---|
| 단계(진행 중) | primary-soft/primary-text | “견적 동의 대기” |
| 단계(완료·통과) | success-soft/success-text | “완료”, “검수 통과” |
| 단계(진행 종료) | surface-sunken/text-muted | “거절함”, “취소됨” |
| 보류 사유 | warning-soft/warning-text | “정보 부족”, “대기”, “보류” |
| 이슈 | danger-soft/danger-text | “결제 불일치” |
| 내부 | internal-soft/internal | “내부 전용”, 위험 플래그 |
| 시험 | warning-soft/warning-text + flask | “시험” |
| 버전 | surface-sunken/text | “v3 · 승인됨” |
- 칩 안 라벨은 §5.2 사전 문자열만 사용. 영문 코드는 `title`/상세 보기에서만.

#### C-08 PhaseStepper (대외 5단계 진행)
- 5칸 가로 스텝(접수→시안·견적→결제·제작준비→제작 중→배송·완료). 지난 칸 = check 아이콘+success, 현재 칸 = primary 굵은 라벨 + `aria-current="step"`, 다음 칸 = text-subtle. 진행 종료 주문은 스텝 대신 “진행 종료 · 거절함(10월 3일)” 한 줄.
- 현재 칸 아래 내부 단계 라벨(body-sm): “견적 동의 대기”.
- <600: 가로 축약(현재 칸 라벨만 표시 + “2/5단계”).
- 스크린리더: `<ol aria-label="진행 단계">`, 각 `<li>`에 “완료/현재/예정” 숨김 텍스트.

#### C-09 NextActionCard (다음 조치)
- 구성: 제목 “다음 할 일” · 대표 조치 문장(“고객이 견적에 동의했는지 기록하세요”) · 조건 체크리스트(C-10) · 대표 버튼(primary lg) · 보조 버튼들(secondary/tertiary) · 담당 역할 표시(“아버님 계정”).
- 조건 미충족이면 대표 버튼 `aria-disabled` + 체크리스트의 미충족 항목이 빨간 X와 해결 링크.
- 주체가 시스템이면(INQUIRY_RECEIVED) 버튼 없이 “AI가 정리하고 있어요 · 보통 1분 이내” + 스피너. 2분 넘으면 “수동 검토로 넘어갔어요”로 바뀜.
- 종료 주문: “이 주문은 끝났어요” + 이력 보기 링크.

#### C-10 GateChecklist (전이 조건 목록)
- 항목: 충족 = check-circle success + 문장, 미충족 = x-circle danger + 문장(§5.4 문구) + 해결 링크(“결제 탭에서 확인하기”). 리스트 `role="list"`, 각 항목 앞 숨김 텍스트 “충족:”/“미충족:”.

#### C-11 ApprovalDialog (승인 대화상자) — §6.1 패턴
- 크기: 최대 560px, <600은 하단 시트(전체 폭, 최대 높이 90vh).
- 구성 순서(고정): 제목(“견적 v2를 승인할까요?”) → 대상 요약(KeyValueList: 대상·버전·금액·납기 등) → 조건 목록(읽기 전용, 모두 충족 상태여야 열림) → 결과 안내(“승인하면 고객 안내 문서를 만들 수 있어요. 승인한 견적은 고칠 수 없고 새 버전으로만 바꿀 수 있어요.”) → 사유 입력(필요한 동작만) → 확인 체크박스(“위 내용을 확인했습니다”, 기본 미체크) → 버튼(오른쪽 primary “승인”, 왼쪽 secondary “취소”). 승인자 이름 표시(“승인자: 김OO(아버님 계정)”).
- 확인 체크 전 primary 버튼은 `aria-disabled` + “확인란을 체크해야 진행돼요”.
- 열릴 때 포커스 = 제목, Esc = 취소, 포커스 트랩, 닫힐 때 여는 버튼으로 복귀.

#### C-12 ConfirmDialog (일반 확인)
- 되돌릴 수 있거나 가벼운 동작(대기로 표시, 정보 요청 기록 등)은 대화상자 없이 실행 + 토스트 “되돌리기”(5초)도 쓰지 않는다 — 감사 기록이 남는 동작은 되돌리기 대신 IMPLICIT-12 규칙을 쓴다. 따라서 ConfirmDialog는 **저장 안 한 변경 이탈 확인**과 **파일 교체 확인**에만 쓴다.

#### C-13 Banner
- 범위: 전역(상단 바 아래, 전 화면) / 화면 / 섹션.
- 종류: info · warning · danger · success · test-mode(warning + flask, 닫기 불가). 구성: 아이콘 · 제목(굵게) · 설명 · 동작 링크 1개 · (닫기 가능한 경우) 닫기 버튼.
- 전역 배너 우선순위(동시에 최대 2개, 나머지는 “외 n건” 링크): ① 시험 운영 모드 ② 서버 재기동 백필 결과 ③ 동기화 연결 필요(401) ④ 백업 경고.
- `role`: danger/warning 신규 출현 시 `role="alert"`, 그 외 `role="status"`.

#### C-14 BlockedReason (막힌 이유)
- 버튼 바로 아래(또는 옆, ≥900) body-sm `danger-text` + octagon-alert 16 + 문장 + 해결 링크. 여러 개면 목록. id를 버튼의 `aria-describedby`에 연결.

#### C-15 Toast / FlashMessage
- 서버 리다이렉트 후 플래시(쿠키 1회) → 화면 오른쪽 위(<600은 하단 고정 조치 바 위) 토스트. 성공 4초 자동 닫힘, 실패는 수동 닫기. `role="status"`(실패는 `role="alert"`). 내용 = 무엇이 되었는가(“견적 v2를 승인했어요”).

#### C-16 DataTable / CardList
- 표: sticky 머리, 행 높이 52(내용 2줄 허용), 숫자 오른쪽 정렬, 행 전체가 링크(행 안 첫 셀에 실제 `<a>` — 키보드는 링크로 이동). 정렬 가능한 열은 머리 버튼 + `aria-sort`.
- 페이지당 50행, 하단 페이지 이동 + “총 132건”.
- <900: 카드 목록(카드 = 주문번호·칩 1줄, 고객·상품 1줄, 다음 조치 1줄, 최종 변경 caption).

#### C-17 FileCard
- 썸네일(이미지) 또는 형식 아이콘 · 파일명 · 종류 칩(참고 이미지/시안/CAD 원본/STL/사양서/검수 사진) · 버전 칩 · SHA-256 앞 12자(mono, “전체 복사” 버튼) · 올린 사람·시각 · 접근 정책 표시(“로그인한 운영자만”).

#### C-18 VersionList / DiffView
- 버전 목록: 최신 위, 각 행 = 버전 칩·상태(초안/승인됨/대체됨)·작성자·시각·변경 요약. 승인된 버전 행에는 lock 아이콘.
- 비교: 두 버전 선택 → 필드별 2열(이전/이후), 바뀐 필드만 강조(배경 warning-soft + “바뀜” 텍스트, 색만으로 표시하지 않음). 고객 응답 revision 비교도 같은 컴포넌트.

#### C-19 InternalOnlyPanel
- 배경 `internal-soft`, 왼쪽 4px `internal` 막대, 머리 “🔒 내부 전용 — 고객 문서·문구에 나가지 않아요”(lock-keyhole 아이콘 + 텍스트). 원가·마진·위험 플래그·내부 메모는 이 컴포넌트 안에서만 렌더링한다.

#### C-20 FreshnessIndicator
- 형식: refresh-cw 16 + “Google 응답 · 3분 전 동기화(22:41)” / hand 16 + “수동 기록 · 김OO · 10월 15일 21:10”. 15분 초과면 warning 색 + “동기화가 늦어지고 있어요”.

#### C-21 CopyBlock
- 읽기 전용 텍스트 영역 + “복사” 버튼. 복사 성공 시 버튼 라벨 “복사됨 ✓” 2초 + `aria-live` 알림. 클립보드 API 실패 시 텍스트 전체 선택 + “Ctrl+C를 눌러 복사하세요”.

#### C-22 EvidenceField (증빙 입력)
- 채널(Radio: 카카오톡/전화/방문/기타) + 근거 텍스트(필수, “고객 메시지 요지 또는 대화 링크”) + 파일(선택: 캡처) + 일시(기본 지금, 수정 가능). 근거 텍스트·채널 비면 저장 불가.

#### C-24 CapacityMeter
- “동시 진행 2/3” + 3칸 막대(채운 칸 primary, 상한 도달 시 warning, 초과 시 danger + “초과 1”). `role="meter"` + `aria-valuenow/max`.

#### C-25 EmptyState / Skeleton / ErrorState
- 빈 상태: 아이콘 24 · 제목 · 설명 1문장 · 동작 1개. 예) 주문 목록 “검토 필요” 큐 비었을 때: “검토할 새 의뢰가 없어요 · 새 의뢰는 5분마다 가져와요 · [지금 가져오기]”.
- 로딩: 서버 렌더라 첫 로드는 스켈레톤 없음. 부분 갱신(fetch) 영역만 스켈레톤(회색 막대, 애니메이션은 reduced-motion이면 정지).
- 오류: §8 카탈로그 문구 + 재시도 버튼 + “오류 코드: SYNC-429”(caption, 복사 가능).

#### C-26 NotificationCenter
- 상단 바 bell 아이콘 + 읽지 않음 배지(최대 “99+”). 패널: 탭 “전체/고객 응답 지연/납기 위험/시스템”, 각 항목 = 종류 아이콘·제목·주문번호 링크·시각. 휴지 시간에는 배지 숫자 증가를 07:00까지 보류(내용은 패널에 보임).

#### C-27 Lightbox (이미지 확대)
- `<dialog>` 전체 화면, 이미지 `object-fit: contain`, 확대/축소(+/− 버튼, 휠, 핀치), 이전/다음(←/→), Esc 닫기, 닫으면 썸네일로 포커스 복귀. 대체 텍스트 “고객 참고 이미지 2/3 · ring_ref.jpg”.

#### C-28 KeyValueList
- 데스크톱 2열(라벨 160px `text-muted` / 값), <600 1열(라벨 위). 값이 없으면 “미기재”(text-subtle) — AI가 채우지 않은 값과 고객이 비운 값을 구분해 “고객 미기재”/“AI 확인 필요”.

#### C-29 Tabs (주문 상세 탭)
- `role="tablist"`이지만 각 탭은 실제 URL 링크(서버 렌더). 선택 탭 `aria-current="page"` + primary 밑줄 3px. 탭 라벨 옆 상태 점(미충족 조건이 있는 탭 = danger 점 + 숨김 텍스트 “확인 필요”).
- <900: 가로 스크롤 탭(스크롤 그림자 표시) — 페이지 전체 가로 스크롤은 생기지 않게 탭 영역 안에서만.

#### C-30 SessionLockOverlay
- z=lock, 배경 bg 100% 불투명(뒤 내용 가림), 가운데 카드: 자물쇠 아이콘·“화면이 잠겼어요”·사용자 이름·비밀번호 필드·“잠금 해제” 버튼·“다른 계정으로 로그인” 링크. 포커스 트랩, 뒤 콘텐츠 `inert`.
- 경고 토스트(14분): “1분 뒤 화면이 잠겨요” + “계속 사용” 버튼(`role="alertdialog"`).


#### C-23 SearchField / FilterBar
- 전역 검색: 상단 바, 폭 320(≥900)/아이콘→전체 폭 시트(<900). 주문번호 일부·고객 표시명 부분 일치, 결과 최대 8건 드롭다운(↑↓·Enter), “모든 결과 보기” → `/orders?q=`.
- 목록 필터: 큐 탭 + 정렬 Select(최종 변경순·약속일순·접수순) + 검색 필드. 모든 값은 URL 쿼리에 반영되어 뒤로가기·새로고침 후에도 유지.

## 5. 상태 표현 체계

### 5.1 표기 계층
1. **대외 단계**(Phase, 6개) — PhaseStepper·고객용 문구·목록 그룹.
2. **내부 단계**(Lifecycle, 18개) — 칩·상세·목록 “현재 단계” 열.
3. **보류 사유**(Hold, 4개) — 단계 칩 옆 warning 칩. 단계를 대체하지 않는다.
4. **이슈**(Issue, 7개) — danger 칩 + 주문 상세 상단 이슈 배너.
5. **승인 상태**(5개) — 목록 열·NextActionCard 머리.

### 5.2 라벨 사전 (코드 → 화면 문구, **원본**)
#### 대외 단계
| 코드 | 라벨 |
|---|---|
| RECEIVED | 접수 |
| CONCEPT_QUOTE | 시안·견적 |
| PAYMENT_PREP | 결제·제작준비 |
| MAKING | 제작 중 |
| DELIVERY | 배송·완료 |
| ENDED | 진행 종료 |

#### 내부 단계
| 코드 | 라벨 | 대외 단계 | 칩 종류 |
|---|---|---|---|
| INQUIRY_RECEIVED | 접수됨 | 접수 | 진행 |
| AI_BRIEF_READY | AI 정리 완료 | 접수 | 진행 |

## 6. 공통 UX 패턴

### 6.1 승인(되돌릴 수 없는 결정)
- 대상 동작: 수락·거절·견적 승인·고객 동의 기록·결제 확인·상세 CAD 시작·고객 최종 시안 동의 기록·공장 발주·검수 통과·잔금 확인·발송·완료·취소·Gate 기록·정책 승인·CS 초안 승인.
- 흐름: 대표 버튼 → ApprovalDialog(C-11) → 서버 검증 → 성공 토스트 + 상세 화면 갱신(다음 조치가 바뀜) / 실패 시 대화상자 안에 409 문구 표시(대화상자 유지).
- 사유 필수: 거절, 보류, 상한 초과 수락, 취소, 되돌리기, Gate 미통과로 되돌림, 정정.
- **일괄 승인 없음**: 목록에 다중 선택 체크박스를 두지 않는다.
- 승인 기록 표시: 이력 탭과 해당 카드에 “승인 · 김OO(아버님) · 10월 16일 22:31 · 견적 v2”.

### 6.2 막힘 표시
- 모든 대표·보조 버튼은 `guards.check()` 결과로 상태를 그린다. 미충족 → `aria-disabled` + C-14. 미충족이 2개 이상이면 NextActionCard 체크리스트가 전체 목록을 보여 준다.
- 권한 부족은 버튼을 숨기지 않고 비활성 + “운영자 계정만 할 수 있어요.”(무엇이 가능한지 학습되게).

### 6.3 버전(불변 기록)
- 견적·디자인·CS 초안·정책·고객 응답(revision)은 **고치지 않고 새 버전**. 승인된 버전 화면에는 “고치기” 버튼 대신 “새 버전 만들기”.
- 새 버전이 기존 승인을 무효화하면(새 디자인 → 패킷 무효) 만들기 전 확인 대화상자에 영향 문장 표시: “새 디자인을 올리면 지금 발주 패킷이 무효가 되고 고객 최종 동의를 다시 받아야 해요.”

### 6.4 내부 전용
- C-19 안에만 렌더. 고객 문서 미리보기 화면에서는 내부 패널이 아예 없다(접혀 있는 게 아님).
- 인쇄 스타일시트(`@media print`)는 C-19를 `display:none` 처리(내부 화면 인쇄 시에도 실수 방지) — 단, 고객 문서는 애초에 내부 데이터를 받지 않는다(BD-007).

### 6.5 증빙 입력
- 고객 동의·고객 최종 시안 동의·결제 확인·발송 완료·취소는 C-22 증빙 필수. 증빙 텍스트에 “고객이 송금했다고 함” 같은 메시지만 있는 결제 확인은 G-PAYMENT-EVIDENCE로 막힌다(결제는 네이버 식별자 필수).

### 6.6 데이터 신선도와 시스템 상태
- 상단 바 시스템 상태 표시기: 점 + 짧은 문구. 녹색 “정상 · 3분 전 동기화” / 주황 “동기화 지연 · 18분 전” / 빨강 “연결 필요”. 누르면 `/system`.
- 외부 데이터 블록마다 C-20.
- 카카오 관련 영역 머리에는 항상 hand 아이콘 + “수동 기록 — 실시간 수신 아님”.

### 6.7 저장 안 한 변경

### S-03c 결제 탭 — UI-05(주문 범위)

- 시험 운영 모드(OPS-01·LEGAL-01 미통과)에서는 폼 위 warning “시험 운영 모드 — 실제 고객 정보를 입력하지 마세요”.
- 폼: 고객 표시명(필수) · 회신수단(카카오톡/전화/기타 + 값, 필수) · 제품 유형(필수) · 설명(필수) · 참고 이미지(선택) · 접수 경로(카카오톡/전화/방문) · **개인정보 동의 증빙**(EvidenceField, 필수 — “폼 밖에서 받은 동의를 어떻게 확인했는지”) · 동의 문구 버전(현재 버전 자동).
- 저장 → 주문 생성(출처 “수기”) → 주문 상세로 이동, AI 정리 시작.

## 13. 구현 가이드

### 13.1 파일 구조(PBS-005)
```
web/templates/
  base.html            # 랜드마크, 상단 바, 사이드바, 전역 배너 슬롯, 토스트 영역, 잠금 오버레이
  components/*.html    # Jinja 매크로: button, chip, banner, next_action, checklist, approval_dialog, kv, file_card, empty, freshness, copy_block, evidence
  screens/*.html       # S-xx별 템플릿
web/static/css/tokens.css  # design-tokens.json → CSS 변수(빌드 없이 손으로 동기화, TC가 JSON과 대조)
web/static/css/app.css     # 레이아웃·컴포넌트 (BEM: .c-button--primary, .l-detail, .s-dashboard)
web/static/js/app.js       # 점진적 향상: 세션 잠금, 저장 경고, 복사, 대화상자, 라이트박스, 대시보드 갱신, 서비스 워커 등록
web/static/sw.js           # 오프라인 셸(E-27)만 캐시
```
- **JS 없이도 핵심 동작**: 모든 승인·저장은 form POST + 303으로 동작. 대화상자는 `<dialog>` + JS, JS가 없으면 별도 확인 페이지(`?confirm=1`)로 폴백.
- **문구 단일 원본**: `domain/labels.py`(§5.2), `domain/guards.py`(§5.4)에 코드-문구 사전. 템플릿은 사전을 통해서만 출력. TC-S-043이 사전 누락·영문 노출 검사.
- **테스트 훅**: 상호작용 요소에 `data-testid="<screen>.<element>"`(예 `order.next-action.primary`). 차단 사유 요소 `data-unmet-code="G-..."`.
- **성능**: 첫 화면 HTML ≤ 100KB(이미지 제외), CSS·JS 합 ≤ 120KB, 폰트는 서브셋 woff2 + `font-display: swap`. 썸네일은 서버가 320px로 축소 캐시.
- **보안 헤더**: CSP `default-src 'self'; img-src 'self' data:; object-src 'none'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`.
